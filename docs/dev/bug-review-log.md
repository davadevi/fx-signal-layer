## 2026-09-07 — Неверный setuptools build backend блокирует установку
- **Где:** `pyproject.toml`, секция `[build-system]`
- **Что:** указан несуществующий backend `setuptools.backends.legacy:build`, поэтому `uv sync --extra dev` завершался до установки проекта
- **Как поймали:** пробная установка проекта после переноса UI
- **Фикс:** использовать стандартный backend `setuptools.build_meta`
- **Не повторять:** проверять изменения структуры репозитория через чистую установку проекта

## 2026-09-07 — Перенос UI ломает источник данных и сборку пакета
- **Где:** `ui/export_timeline_data.py`, `pyproject.toml`
- **Что:** после переноса `ui/` в корень репозитория экспортёр искал отсутствующий `cbr_observations.csv`, а setuptools мог принять `ui` за второй namespace-пакет в flat layout
- **Как поймали:** проверка относительных путей и package discovery перед переносом
- **Фикс:** перевести экспортёр на канонический `data/processed/rates.parquet`, явно включить только пакеты `src*`
- **Не повторять:** при добавлении верхнеуровневого каталога проверять вычисляемые пути и automatic package discovery

## 2026-09-06 — Глобальный cooldown блокирует все коридоры
- **Где:** `src/pipeline/signals.py`, `signal_history` — плоский список дат
- **Что:** история cooldown общая для всех коридоров; если TJS дал сигнал в день X, KGS тоже блокируется на cooldown_days, хотя это независимый коридор
- **Как поймали:** code review от второго инженера (validation_findings.csv)
- **Фикс:** изменить тип `signal_history` на `dict[str, list[date]]`, cooldown проверять per-corridor
- **Не повторять:** cooldown всегда per-corridor, не глобальный по дате

## 2026-09-06 — CI считался на полной выборке, а не на OOT
- **Где:** `src/backtest/engine.py`, вызов `lift_confidence_interval`
- **Что:** `lift_ci_low/high` вычислены из `all_signals + all_trading_days`, а не из `oot_signals + oot_trading_days`; заявленная устойчивость на OOT не подтверждена
- **Как поймали:** code review (validation_findings.csv, критическая)
- **Фикс:** добавить отдельные поля `lift_ci_low_oot/high_oot`, вычислять из OOT-подмножества
- **Не повторять:** CI для OOT-заявлений всегда на OOT-данных, не на полной выборке

## 2026-09-06 — CI confidence level 95% вместо 90%
- **Где:** `src/backtest/metrics.py`, `lift_confidence_interval(confidence_level=0.95)`
- **Что:** дефолт 0.95, но продуктовое решение команды — 90%; engine не передавал явно, значит считал 95%
- **Как поймали:** расхождение между документом submission (пишет 90%) и дефолтом функции
- **Фикс:** изменить дефолт на 0.90, передавать явно при вызове из engine
- **Не повторять:** уровень доверия — явный параметр, не дефолт в функции

## 2026-09-06 — max_h обрезает тестовые данные для малых горизонтов
- **Где:** `src/backtest/engine.py`, `last_test_end = data_end - timedelta(days=max(horizons))`
- **Что:** добавление h=30 в список горизонтов обрезает `last_test_end` на 30 дней назад; теряется 10 дней тестовых данных для h=1..20, так как `last_test_end` определяет конец последнего тестового окна
- **Как поймали:** code review (validation_findings.csv)
- **Фикс:** `last_test_end = data_end - timedelta(days=min(horizons))`; eligibility per-signal per-h уже проверяет `_forward_hits`
- **Не повторять:** cutoff для тестового окна не зависит от максимального горизонта
