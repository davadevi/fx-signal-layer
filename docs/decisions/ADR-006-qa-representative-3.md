# ADR-006: Q&A с кейсодателем — сессия 3 (2026-09-03)

**Источник:** «Ответы на вопросы команд и комментарии кейсодателя», Альфа Будущее, 2026-09-03

---

## Три ключевых положения (снимают большинство вопросов)

1. **Решения оцениваются на уровне выводов, а не допущений.** Постановка не фиксирует горизонт, порог выгоды, окно расчёта, портрет клиента, поведение в тихий месяц, канал пуша. Команда формулирует допущение, оценивает результат при нём и защищает лучший вариант с обоснованием.

2. **Фокус кейса — триггерные коммуникации.** Два направления: (а) триггерные коммуникации — чистый эффект информационных триггеров на воронку; (б) триггерное ценообразование — эффект коммуникации + скидка/надбавка в спреде. **Кейс — про первое.**

3. **Сверх презентации оцениваются:** инструкция по запуску, план пилота, перечень ограничений, тайминг защиты.

## Метрики и бэктест

| Вопрос | Ответ кейсодателя |
|--------|-------------------|
| Что такое «случайный день» для uplift? | Точность сигнала / точность случайного дня в том же коридоре и периоде. Попадание для «сейчас выгодно» — курс не хуже через h дней (h = 1/3/5/10/20). Выгода момента = курс в день сигнала vs среднее окружающих ±h дней — считается отдельно. |
| Lift ≥ 1.3 — по точности или по bps? | **По точности (hit rate).** Выгода в базисных пунктах — отдельное обязательное условие годности. |
| Что значит «устойчиво»? | Одновременно на нескольких коридорах и на out-of-time окнах walk-forward — не в среднем по всей истории. |
| Какие периоды в бэктест, как трактовать 2022? | Постановка периоды не фиксирует. Команда берёт логичные предпосылки и явно обосновывает. |
| Корреляция коридоров с USD/RUB — «несколько коридоров» = независимое подтверждение? | Независимости не требуется. «Несколько коридоров» — проверка переноса параметров с коридора на коридор. |
| Вероятность 90/95/99% — какую выбрать? | Шкала самопроверки, выбор за командой с обоснованием. |
| Индикатор «снижается N дней подряд» даёт lift < 1. Мы неверно читаем? | Прочли верно. Отрицательный результат засчитывается. Это пункт 6 постановки «быстрые vs медленные» — нужна цифра цены ожидания. |
| Порог bps/рублей, ниже которого не запускать? | Постановка — «значимо больше нуля». Порог — продуктовая работа команды. |
| Выгода момента только вперёд (не ±h)? | Допущение команды. Постановка задаёт ±h как определение; отступление — обосновывается. |
| ЦБ: на дату T доступен курс T, горизонт от T+1? | Допущение команды. Требование одно: сигнал на T считается по данным, доступным на T. Лаг: курс на завтра публикуется сегодня. |
| Выходные/праздники исключать и из базы, и из сигналов? | Допущение команды. |
| Какой горизонт (1/3/5/10/20) главный? | **Главный не выделен. Метрики нужны по всем пяти.** |
| Перевод по сигналу — доп. объём или каннибализация? | Инкрементальный объём и каннибализация на хакатоне не измеряются. Нужны как рамка. |

## Данные и курс

| Вопрос | Ответ |
|--------|-------|
| Курс приложения vs курс ЦБ — есть лаг? | Курс приложения реального времени, привязан к поставщикам ликвидности. MOEX можно использовать как индикатор внутридневной динамики. |
| Фиксация курса на 2ч/2дня как фича? | Допустимо, если обсчитана: издержки, выгоды, условия, поведение при высокой волатильности. |
| Внутридневной ряд TJS/UZS/KGS/AMD через кросс USD/RUB? | Приемлемо. Ограничение: данные открытые и воспроизводимые. Допущение фиксируется явно. |
| Обезличенные данные по клиентам/когортам? | **Не предоставляются.** Строить на обоснованном портрете аудитории и/или синтетическом потоке. |
| Бенчмарк по пушам (CTR, конверсия, отписки)? | **Не предоставляются.** |
| Доступ к приложению/скриншотам? | Отдельного доступа нет. Приложение публично в магазинах. |

## Продукт и тексты

| Вопрос | Ответ |
|--------|-------|
| Лимит 1–2 пуша/неделю — на валюту или на клиента? | **На клиента суммарно.** Сигнал о курсе конкурирует с другими коммуникациями. Частота 1–2/неделю на коридор в постановке — самопроверка фильтров; кучность измеряется отдельно. |
| Тихий месяц — молчать или слабый сигнал? | Допущение команды. |
| Сомони — приоритет или иллюстрация? | **Иллюстрация.** Коридор для пилота не задан. Подходит любая валюта из доступных стран. |
| Портрет клиента: переводит раз в месяц после зарплаты, один коридор? | Допущение команды. |
| «Сейчас невыгодно, подождите» — пуш или молчание? | Команда определяет, какие сценарии дают пуш. |
| Граница текстов: «успейте перевести» vs «успейте, пока не подорожало»? | Рамка: говорим о настоящем и прошлом, вывод клиент делает сам. Обещать/предсказывать нельзя ни прямо, ни намёком. Конкретную формулировку оценивает команда — осознанность учитывается при оценке. |

## Обязательные артефакты сверх презентации

Из критериев организаторов (общих для всех кейсов):

1. **Инструкция по запуску** — репо + описание по которому посторонний повторяет результат: окружение, команда запуска, источник данных.
2. **План пилота** — что нужно от банка, метрики пилота, срок набора событий при текущей частоте сигналов, риски. Таргетинг и интеграции вне скоупа, но назвать как условия пилота нужно.
3. **Ограничения, риски, компромиссы** — отдельный раздел: что решение не умеет, какие развилки были и почему выбрали именно так.
4. **Тайминг защиты** — укладывается в отведённое время, отвечать по существу на вопросы по метрикам и ограничениям.

## Алгоритм работы с неопределённостью (7 шагов от кейсодателя)

1. Что делаю, чего хочу, какая цель.
2. Как неопределённость влияет и механизм влияния.
3. Что нужно для принятия решения (много «вопросов на посмотреть» оказываются лишними).
4. Как снизить неопределённость — структурировать на возможные исходы.
5. Помогут ли внешние данные.
6. Можно ли использовать прокси или открытые данные.
7. Если данных нет — описать развилку и показать алгоритм/правила, как действовали бы внутри банка.

## Импликации для нашего решения

- **Lift считать по hit rate**, не по bps. Bps — отдельный критерий годности.
- **Устойчивость** — одновременно на 5 коридорах И на out-of-time окнах, не в среднем.
- **Все 5 горизонтов** (1/3/5/10/20) обязательны в отчёте.
- **Частота 1–2/неделю на коридор** — фильтр внутри нашего пайплайна, не глобальный лимит клиента.
- **Отрицательный результат** по индикатору засчитывается — логировать в iteration log.
- **Нет внутренних данных** — всё строить на ЦБ + MOEX + открытых источниках.
- **README + launch script** нужны как часть сдачи — не опциональны.
- **Тексты**: граница — настоящее/прошлое. «Успейте перевести» разрешено (факт о текущем курсе), «пока не подорожало» — запрещено (намёк на будущее).
