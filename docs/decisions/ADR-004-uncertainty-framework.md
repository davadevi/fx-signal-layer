# ADR-004: Фреймворк принятия решений при неопределённости

**Дата:** 2026-09-02  
**Источник:** Сообщение кейсодателя после Q&A сессий  
**Статус:** Обязательный принцип для команды

---

## Суть

90% вопросов к заказчику можно закрыть самостоятельно. Алгоритм:

1. **Что делаю / чего хочу / какая цель** — не проскакивать, формулировать явно
2. **Как неопределённость влияет** — какой конкретный механизм, не абстрактно
3. **Что нужно чтобы принять решение** — часто вопросы оказываются лишними
4. **Снизить неопределённость** — структурировать на возможные исходы
5. **Помогут ли внешние данные** — открытые, воспроизводимые
6. **Можно ли использовать прокси** — идти дальше без ответа заказчика
7. **Если решение прямо сейчас** — описать развилку + алгоритм как действовали бы внутри банка (реалистично оценивая что там есть и чего нет)

---

## Применение к нашим открытым вопросам

### Тихий месяц: молчать или слать слабый сигнал?

1. Цель: не выжечь канал, сохранить доверие клиента
2. Неопределённость: не знаем CTR слабого сигнала vs отсутствия
3. Нужно для решения: данные об усталости от пушей — их нет
4. Исходы: (А) молчим → клиент не раздражён, но пропускает месяц; (Б) слабый сигнал → риск FP, выгорание
5. Внешние данные: индустриальные бенчмарки говорят нерелевантный пуш снижает CTR следующего на 15–30%
6. Прокси: асимметрия цены ошибки из ТЗ — FP дороже FN
7. **Решение: молчать.** Логировать «тихий период», не слать ниже порога.

### Лимит: как приоритизировать коридоры при конкуренции?

1. Цель: максимизировать ценность единственного пуша в неделю
2. Неопределённость: не знаем какой коридор важнее для клиента
3. Нужно: данные о частоте переводов по коридорам — их нет
4. Исходы: (А) по силе сигнала; (Б) по волатильности коридора; (В) случайно
5. Внешние данные: TJS и UZS — самые волатильные исторически
6. Прокси: сила сигнала (percentile score) как прокси ценности
7. **Решение: приоритет по силе сигнала.** Strongest signal wins. Фиксируем в pipeline.

### Горизонт h: какой акцентировать в презентации?

1. Цель: показать реалистичную выгоду для клиента
2. Неопределённость: не знаем через сколько дней клиент реально переводит
3. Нужно: распределение переводов по дням после зарплаты — нет
4. Исходы: h=1 (переводит завтра), h=5 (в течение недели), h=20 (в этом месяце)
5. Внешние данные: портрет клиента — переводит раз в месяц, окно ±5 дней от зарплаты
6. Прокси: h=5 как реалистичное окно гибкости
7. **Решение: h=5 как основной, остальные в таблице.**

---

## Правило для команды

Перед тем как задавать вопрос заказчику — прогнать через этот фреймворк.  
Если на шаге 6 есть прокси или внешние данные → решить самостоятельно и зафиксировать допущение в ADR-003.  
Вопрос к заказчику только если шаги 4–7 не дают ответа.
