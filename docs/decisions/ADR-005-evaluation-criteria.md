# ADR-005: Критерии оценки организаторов

**Дата:** 2026-09-02  
**Источник:** Организаторы хакатона — общие критерии для всех кейсов  
**Статус:** Обязательно реализовать до защиты

## Что добавляется к требованиям кейса

### 1. Инструкция по запуску (воспроизводимость)

Репозиторий должен позволять постороннему человеку повторить результат:
- Описание окружения (Python версия, зависимости)
- Команда запуска — одна команда воспроизводит весь результат
- Откуда берутся данные — ссылка на источник, команда загрузки
- Ожидаемый вывод — что должно появиться после запуска

### 2. План пилота

Отдельный раздел в отчёте. Должен отвечать на:

**Что нужно от банка:**
- Доступ к реальным курсам исполнения (не только ЦБ)
- Сегмент клиентов для A/B теста (целевые + холдаут)
- Интеграция с пуш-платформой (технические условия, не скоуп хакатона — но назвать)
- CRM-данные для таргетинга (вне скоупа — назвать как условие)

**Метрики пилота:**
- Основная: инкрементальная конверсия (% клиентов, сдвинувших перевод vs холдаут)
- Net-объём переводов через сигнальный день vs холдаут
- Каннибализация будущих переводов (контроль)
- CTR пуша
- Отписки от пушей (контроль выгорания канала)

**Тайминг набора событий:**
- При 1–2 сигналах/коридор/неделю × 5 коридоров = 5–10 сигналов/неделю
- Минимум событий для статзначимости: ~200–300 на группу
- При охвате X клиентов → оценить сколько недель нужно (зависит от размера когорты)

**Риски пилота:**
- Стale rate: курс изменился между пушем и открытием → механика экрана (звёздочка)
- Каннибализация: клиент перевёл раньше обычного, следующий перевод сдвинулся позже
- Выгорание канала при низком качестве сигнала
- Регуляторный риск: текст пуша должен пройти compliance до запуска

### 3. Ограничения, риски и компромиссы

Отдельный раздел отчёта. Структура:

**Что решение не умеет:**
- Не предсказывает курс — только детектирует статистически выгодный момент
- Не учитывает клиентский контекст (частота переводов, сумма, дата зарплаты)
- Работает на курсе ЦБ, не на курсе исполнения в приложении
- Не адаптируется к режиму рынка в реальном времени (пересчёт раз в день)

**Принятые компромиссы:**
- 2022 исключён из обучения → меньше данных, но релевантнее
- Лимит глобальный → нужен приоритизатор, пока простой (strongest signal wins)
- Выгода считается forward-only → честнее, но занижает метрику vs симметричного окна
- Молчание в тихий месяц → пропускаем клиентов, но не выжигаем канал

**Известные риски модели:**
- Momentum-reversal (reversal работает, momentum нет) — задокументировать
- Высокая корреляция коридоров с USD/RUB → "несколько коридоров" не независимы
- 2025–2026: нестабильный lift → объяснить причину

### 4. Тайминг защиты

- Выступление в отведённое время (уточнить у организаторов)
- На вопросы по метрикам и ограничениям отвечать по существу
- Подготовить: матрица индикатор × коридор × метрики, график курса с сигналами, сквозной сценарий
