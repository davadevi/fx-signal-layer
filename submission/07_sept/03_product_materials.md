## 1. Целевая аудитория

### 1.1 Портрет клиента

> Трудовой мигрант из СНГ, работает и получает зарплату в РФ. Раз в месяц (после зарплаты) переводит фиксированную часть дохода одному получателю в одной стране — **один коридор, один получатель**. Курс не отслеживает: открывает приложение по внешнему поводу (пришла зарплата, попросили из дома), а не потому что «сегодня выгодно». Находится в часовом поясе получателя или близком к нему (например, UZS/KGS-коридоры — UTC+5, разница с Москвой 2 часа) — это напрямую определяет, какие часы для пуша «живые», а какие — мусор.

**Почему такой портрет, а не «активный трейдер валюты»:** большинство переводов в СНГ регулярные и привязанные к зарплатному циклу, а не оппортунистические. Это соответствует и baseline кейса («случайный день» = когда попало), и ограничению банка — лимит коммуникаций считается суммарно на клиента, а не на коридор (см. раздел 4, H2).

**Продуктовое следствие часового пояса:** запрещаем окно 22:00–08:00 по времени получателя/отправителя, что бы ни говорил сигнал. Математически верный сигнал в 01:00 по местному — для продукта мусор.

## 2. Проблематика

| Как сейчас | Стоимость боли |
|---|---|
| Клиент открывает приложение по внешнему поводу, а не по курсу | Момент перевода случаен относительно курса |
| Курс виден в моменте, без истории и контекста | Невозможно понять, сегодня хорошо или плохо, не сравнивая самостоятельно |
| Сравнение банков отвечает на вопрос о спреде, а не о времени | Клиент решает не ту задачу — ищет банк подешевле, а не удачный день |
| Разброс официального курса ЦБ RUB→TJS внутри месяца: медиана 5,9%, максимум 9,4% (июнь 2026) | Реальные деньги: разница в несколько % от суммы перевода |

**Формула успеха, которую мы обязаны обыграть:** baseline — случайный день (клиент переводит когда попало). Модель обязана давать:
1. **uplift ≥ 1,3** по hit rate (точность сигнала / точность случайного дня в том же коридоре и периоде), устойчиво по нескольким коридорам и walk-forward OOT-окнам одновременно — не как исторический средний показатель;
2. **отдельно** — положительную экономическую выгоду в базисных пунктах (курс в день сигнала против среднего курса окружающих ±h дней).

Это два разных условия годности: высокий uplift при близкой к нулю или отрицательной выгоде в б.п. не считается успехом.

**Попадание считается pathwise:** для сообщения «сейчас выгодно» курс не должен становиться хуже ни в один из h дней горизонта (h = 1/3/5/10/20) — а не только в конечной точке T+h. Клиент может открыть пуш не сразу, поэтому гарантия «не хуже» должна держаться на всём окне, а не в одной точке.

## 3. Ценностное предложение

**Одной фразой:** мы не показываем курс — мы говорим, когда о нём стоит подумать, и делаем это фактами о прошлом, а не обещаниями о будущем.

### 3.1 Чем отличаемся от аналогов

| Аналог | Что делает | Чем мы отличаемся |
|---|---|---|
| Курс-трекеры (XE, «Курс валют», Wise rate alerts) | Показывают текущий курс, алерт на порог, заданный пользователем вручную | Момент определяет сигнальный слой (индикаторы + ML), клиенту не нужно самому настраивать пороги |
| Push брокеров/бирж о движении актива | Ловят резкое % движение | Комбинируем несколько типов сигналов (моментум, уровень, разворот, сезонность), калибруем под частоту коммуникации, а не под сырую волатильность |
| Wise/Remitly «best time to send» | Дают исторический контекст курса | Explainable ML-слой с walk-forward валидацией и явным запретом на прогноз |
| E-commerce push «цена упала — успей купить» | Учат механике срочности | Обязаны избегать любых формулировок про будущее — только факты о прошлом/настоящем |

### 3.2 Value Proposition Canvas

| Customer Profile | Value Map |
|---|---|
| **Jobs (functional):** перевести деньги семье, не потеряв на курсе просто потому, что «перевёл когда вспомнил» | **Products & Services:** сигнальный push с фактом о курсе + предзаполненная форма перевода (сумма, получатель, коридор) |
| **Jobs (social):** быть человеком, который заботится о семье осознанно, а не спустя рукава | **Pain relievers:** снимает необходимость ежедневно следить за рынком; факт вместо прогноза снижает риск ощущения «обмана» при открытии пуша позже |
| **Jobs (emotional):** спокойствие — решение принято осознанно | **Gain creators:** до получателя в среднем доходит больше денег при следовании сигналам; осознанность решения без дополнительных усилий клиента |
| **Pains:** не знает, выгодный ли сегодня момент; тратить время на слежку самому; чувство, что переплатил «просто по привычке» | |
| **Gains:** уверенность в решении; больше денег получателю; не нужно самому анализировать курс | |

### 3.3 Принцип коммуникации

Push — это факт, а не прогноз. Допустимая формулировка: «Сейчас курс лучше, чем в 85% дней за последние 3 месяца». Недопустимо: «успейте», «выгодный курс продержится недолго», любые формулировки, подразумевающие обещание будущего движения курса.

| # | Гипотеза (кратко) | Тип | Метрика проверки | Статус после первого цикла бэктеста |
|---|---|---|---|---|

| **H4 (*)** | Одна методология калибровки переносится между коридорами (TJS/UZS/KGS/AMD/KZT) без ручной перенастройки с нуля | Продуктовая, самая рискованная | uplift ≥1,3 на каждом коридоре при одной методологии | **Оценивать преждевременно.** Пока нет ни одной конфигурации, устойчиво прошедшей критерии годности хотя бы на одном коридоре. KZT и UZS показывают структурно иное поведение рынка |
| **H5** | Быстрый индикатор (2–3 дня) даёт больший uplift, чем ожидание подтверждения медленным (30 дней) | AI | цена ожидания в б.п. | **Не подтверждена в текущей формулировке.** Быстрый индикатор слабее медленного по point lift на всех коридорах, но и медленный не проходит обязательный порог устойчиво — сравнение «цены ожидания» пока некорректно |
| **H6 (звезда)** | Экран «курс на момент пуша vs сейчас» с одной кнопкой снижает ощущение обмана при отложенном открытии | Продуктовая, звёздочка | Качественная проверка | В работе; приоритет — после закрытия сигнального слоя |
| **H7** | Сезонный индикатор (праздничный календарь) даёт редкие, но полезные сигналы | Продуктовая | Доля потока, устойчивость lift | В бэктесте: добавление календарных сигналов расширяет частоту, но снижает lift — эффект разбавления edge |

### 4.1 Как это читать бизнесу

Ни один статус не означает, что продукт не состоялся. H1 и H2 закрыты штатно: H1 — честным отрицательным результатом, H2 — явным продуктовым решением кейсодателя. H3–H5 показывают, что метод пока не готов к пилоту: point lift выше 1,3 виден на нескольких коридорах и горизонтах (KGS, TJS, AMD), но не проходит одновременно через все обязательные фильтры — устойчивую нижнюю границу, положительную выгоду в б.п. и целевую частоту 1–2 сигнала в неделю. Это ожидаемый исход первой итерации количественного сигнала, и его честная демонстрация — часть продуктовой работы.

### 4.2 Что именно ограничивает текущий результат

- **Устойчивость границы.** Сильный правиловый индикатор (моментум с подтверждением разворота) даёт point lift 1.3–1.6 на TJS/KGS/AMD, но нижняя граница (block-bootstrap с учётом автокорреляции курса) остаётся ниже целевого порога — выборка сигналов слишком мала (10–14 на коридор за весь период), доверительный интервал широкий.
- **Экономика на коротком горизонте.** На горизонте h=5 сильный сигнал показывает отрицательную среднюю выгоду в б.п. на всех пяти коридорах — направление угадывается верно, но сигнал приходит уже после того, как выгодная часть движения курса состоялась.
- **Частота.** Устойчивый по качеству сигнал редкий — около 0,05–0,1 срабатывания в неделю на коридор, в 10–20 раз реже продуктовой цели 1–2/нед. Наивное расширение потока дополнительными (optional) сигналами возвращает частоту к цели, но одновременно роняет lift обратно к уровню случайного дня.
- **KZT и UZS структурно другие.** KZT — более институциональный, не ремитентный поток; UZS — менее ликвидный рынок. Единая конфигурация индикатора не даёт на них того же edge, что на TJS/KGS/AMD — потенциально нужны отдельные признаки (например, внешние данные по нефти Brent, коррелирующие с рублём).

## 5. Границы MVP и основной пользовательский сценарий

### Входит в MVP

- 5 коридоров: RUB/TJS, RUB/UZS, RUB/KGS, RUB/AMD, RUB/KZT
- Один тип сигнала: «выгодный момент сейчас» (favorable_now)
- Push-текст на русском языке, compliance-validated (только факты прошлого)
- Ограничение часового окна: запрет пуша в 22:00–08:00 по времени получателя
- Cooldown 3 дня между сигналами по коридору; лимит суммарно на клиента (не на коридор)
- Экран: курс на момент пуша + предзаполненная форма перевода (H6)

### Не входит в MVP

- Персонализация порога под клиента
- Отрицательный сигнал («курс невыгоден — подождите»)
- Прогноз курса на будущее
- Межкоридорная алгоритмическая приоритизация (H2 закрыта: оставляем банку)
- Поддержка коридоров за пределами 5 целевых

### Основной пользовательский сценарий

```
1. Клиент переводит деньги по коридору RUB/KGS раз в месяц.

2. Система ежедневно вычисляет индикатор по всем 5 коридорам
   с cutoff_date = сегодня (после публикации курса ЦБ).

3. Индикатор срабатывает по KGS: score = 0.12 (log-return
   в нижних 12% за 60 дней), подтверждение на следующий день.

4. Проверки: режим не кризисный / cooldown не истёк /
   лимит на клиента не превышен / время в допустимом окне.

5. Система генерирует push-текст:
   «Рубль укрепился к сому за последние 5 дней сильнее,
   чем в 88% случаев за 3 месяца. Текущий курс: 1.4320 руб.»

6. Клиент видит уведомление → экран с курсом на момент пуша
   vs текущий курс → одна кнопка → предзаполненная форма перевода.
```

## 7. Допущения, риски и план проверки

### Зафиксированные допущения

| Параметр | Решение | Обоснование |
|----------|---------|------------|
| Тихий месяц | Молчание, не слабый сигнал | Асимметрия: FP > FN |
| Уровень доверия CI | 90% | Баланс частоты и точности; порог совместно с заказчиком |
| Клиентский горизонт | h = 5 рабочих дней | Типичный лаг принятия решения |
| Источник данных | ЦБ РФ, дата публикации | Исключает lookahead |
| Невыгодный курс | Молчание | Асимметрия, усталость от уведомлений |
| Формулировка «Успейте» | Запрещена | Срочность = имплицитный прогноз |
| Лимит пушей | Суммарно на клиента, не на коридор | Решение кейсодателя (H2) |
| Окно пуша | Запрет 22:00–08:00 по времени получателя | Мусорное время для аудитории |

### Ключевые риски

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| Частота < 1 сигн./нед после OOT | Высокая | Weak-tier (confirm=0) + отдельный cooldown |
| bps отрицательные → продукт не экономит деньги | Высокая | Пересмотр horizon; проверка более длинного h=10/20 |
| Клиент не реагирует на push | Средняя | A/B пилот с контрольной группой; H6 снижает риск «обмана» |
| KZT/UZS не поддаются единой методологии | Средняя | Отдельные признаки (Brent, ликвидность); ограничение MVP до KGS/TJS/AMD |
